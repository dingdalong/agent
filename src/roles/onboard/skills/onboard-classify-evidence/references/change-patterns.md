### dimension = change-patterns

发现项目自身重复出现的开发任务形状，为后续按需技能提供证据。**不得从通用游戏知识预设系统列表或强行凑技能。** 候选发现方法：

1. 结合仓库地图的注册入口、测试布局和生成步骤，找出重复的改动形状；卡是每个模块的单点证据，跨模块的一次真实改动靠 Git 历史与 `cross-module.md` 账本已核实关系串联。
2. Git 可用时，shell 只跑只读 `git log`、`git show`、`git diff`，查看代表性提交，确认一次真实改动**跨模块**涉及的文件集合与先后关系；不得根据提交标题单独下结论。
3. Git 不可用时，横向比较多张卡中形状相似的模块，重建共同的定义、注册、实现、持久化、测试和生成步骤，并降低历史覆盖说明。

**技能候选门槛**——候选任务只有满足以下任一条件才能进入技能候选：

- 存在两个独立完整案例，且关键步骤、文件角色和验证方式一致；
- 存在明确的生成器或框架模板，并至少有一个实际消费者证明使用方式。

单一案例、只重复类名的代码、无法追完整链路的片段或存在未解决冲突的模式，不生成技能候选，只写入参考或未知项。每个候选任务记录：稳定英文 slug 候选与精确触发描述、适用与不适用场景、源文件/生成物/注册点/测试文件的角色清单（而非固定绝对文件名模板）、实施顺序与每步前置条件和验证方式、两个独立完整案例或生成器模板的函数/字段级引用、常见偏差与必须交由用户裁决的部分。报告结构：

```markdown
# Change Patterns Evidence
## 仓库快照与分析范围
## 覆盖情况与历史可用性
## 候选任务发现方法
## 已达门槛的技能候选
## 未达门槛的重复模式
## 证据发现
## 冲突与未知项
```

技能候选额外注明案例数量、覆盖模块和验证命令的项目内实际调用位置。仅有工具配置而没有调用位置时不得把命令带入技能候选。
