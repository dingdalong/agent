## 形成具体方案

先确定请求是创建、修改、执行还是删除，并查询实际场景或自动化详情。创建与修改需要确定名称、手动或自动触发方式、条件及设备动作；复用用户已经给出的信息，只询问影响方案的缺口。

查询涉及设备及其能力，核对动作参数、条件和房间范围。用具体设备、触发条件、动作和参数说明方案，不用未查询的能力填充方案。

## 确认与执行

创建、修改须有用户对具体方案的确认，删除须确认具体目标；已有明确确认且方案未变时直接执行，不重复提问。缺少确认时主 agent 展示方案并询问；子 agent 返回待确认方案并结束，由主 agent 沟通后发起包含完整输入的新委派。

执行场景前核对实际动作是否在用户授权范围内。涉及门锁、安防或燃气等安全敏感设备时遵循共同准则，由主 agent 处理；不得用场景包装绕过逐次确认，也不得把需逐次确认的操作配置为无人确认的自动执行。

使用实际注册的 MCP 工具执行已确认操作。调用失败或超时时先核对是否已经生效，避免重复创建或重复执行；缺少工具、权限或输入时返回具体阻碍。

## 复核与报告

创建或修改后查询详情，核对名称、启用状态、触发条件及每项设备动作；删除后确认目标已不存在。执行场景后查询各目标设备实际状态，逐项区分成功、失败和未验证，不能仅凭场景接口返回成功就宣称全部设备达标。

报告实际操作、验证证据及未完成项。局部失败如实呈现，不未经授权回滚其他设备或改动无关规则。
