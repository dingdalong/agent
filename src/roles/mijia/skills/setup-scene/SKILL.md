---

## 前置条件

- 已连接米家 MCP server，设备列表可查询。
- 由主 agent 按需加载，或用户明确要求创建场景时加载。

## 工作流

### 第 1 步：了解需求

向用户确认以下信息（缺一不可）：
1. 场景名称（如"回家模式"、"观影模式"）
2. 场景触发方式（手动 / 语音 / 自动化条件）
3. 涉及哪些房间（全部 / 指定房间）

### 第 2 步：枚举可用设备

使用查询工具列出相关房间的所有设备。向用户展示设备清单：

```
## 可用设备

| 房间 | 设备 | 类型 | 当前状态 |
|------|------|------|----------|
| 客厅 | 吸顶灯 | light | 关闭 |
| 客厅 | 灯带 | light | 关闭 |
| 客厅 | 空调 | ac | 关闭 |
| 客厅 | 窗帘 | curtain | 打开 |
```

### 第 3 步：提出场景方案

基于用户需求和可用设备，提出具体场景方案：

```
## 场景方案

场景名：回家模式
触发：手动 / 语音

| 设备 | 动作 | 参数 |
|------|------|------|
| 客厅吸顶灯 | 开启 | 亮度 80%，色温 4000K |
| 客厅灯带 | 开启 | 亮度 50%，暖光 |
| 客厅空调 | 开启 | 制冷 26°C，自动风 |
| 客厅窗帘 | 关闭 | — |
```

### 第 4 步：用户确认

将方案提交给主 agent，由主 agent 向用户确认。不可自行跳过确认。

### 第 5 步：创建场景

用户确认后，调用场景创建工具创建场景。

### 第 6 步：复核

创建后查询场景列表，确认新场景已存在并包含正确的设备和动作。
将结果报告给主 agent。

## 严格限制

- 每一步都必须有输出，不可跳过。
- 第 4 步必须等待用户确认，不可自动通过。
- 涉及安全敏感设备（门锁等）时额外警告。
- 场景创建失败时报告错误详情，不重试超过 2 次。
