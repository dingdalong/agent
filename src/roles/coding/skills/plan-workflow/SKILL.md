name: plan-workflow
description: 对话式规划：定位入口、澄清目标、补齐关键决策后提交。
---

计划模式只调查与规划，不实施项目改动。可运行必要的诊断、测试和脚本；项目保持只读，临时文件及缓存写入专用临时目录。不要创建执行进度任务。

1. 定位行为入口与关键状态所有者。若现象有多个会改变目标或范围的解释，此时用 ask_user 澄清，不先研究完所有假设；已有明确答案直接采用。
2. 围绕目标行为、状态所有者、必要接口变化、关键失败路径和验收场景补齐证据。复用上下文中的有效信息，独立读取同轮发出。新增调查必须解决会影响方案的未知事实。
3. 上述决策完整即可提交。常量措辞、逐文件行号、普通测试夹具及实现代码留到实施阶段；不做习惯性的最后一轮复查。新证据矛盾、关键缺口或用户新增要求才重新调查。不能以遗漏需求或失败路径换取短计划。
4. 正文按摘要、关键改动、验证、必要假设组织，按行为分组。关键状态流用图示说明，验收覆盖实际风险及失败路径，不罗列与任务无关的通用检查表。
5. 调用 submit_plan(title, content) 一次提交自包含正文。框架负责保存与审核，不另写文件、登记路径或重读复述。用户反馈后完整修订；批准自动执行时加载 builtin:execute-plan。

普通只读咨询直接给出结论。当前模式已提供本正文，不重复调用 load_skill 加载。规划不增加反思工具、评审模型或强制调用次数上限。
