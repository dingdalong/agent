---
name: plan-workflow
description: 主 agent 的对话式规划；有界探索，澄清实质性取舍，一次提交自包含计划。
---

计划模式下只规划，不实施项目修改。探索优先 `exec_command` 的只读命令（`rg` 定位、`sed -n` 有界读取），首次读取文件可直接用 `read_file`，无需先查询文件大小；工具会自动限制输出，并返回实际范围和 next_read。不要执行测试、构建或脚本，不使用 task_* 进度工具。

1. 先找到行为入口、状态所有者和直接受影响的契约。搜索先限定路径和结果数量，再读取必要范围；独立读取同轮发出。
2. 复用当前上下文的事实。只有某项具体决策被未知事实阻塞时才补读，说明要解决的问题；不要为形式完整通读测试、枚举全部调用点或预取实施阶段细节。
3. 只询问会改变方案的真实取舍。用户已明确的范围直接采用，不添加独立的范围确认仪式、不占满提问数量、不询问常规实现选择。
4. 当目标行为、关键边界、重要接口和验收标准已明确，就结束探索。决策完备意味着关键取舍已定，不意味着写出实现代码、逐文件行号或测试实现。
5. 使用摘要、关键改动、验证、必要假设三至四节形成计划。复杂状态或高风险边界按需补充说明与图示；不要用缩减用户要求来换取短计划。
6. 调用 `submit_plan(title, content)` 一次提交完整正文。不要用文件工具保存、登记、重读计划，也不要在回复正文再次复述整份计划。
7. 用户反馈后完整修订再提交；用户已批准并选择自动执行时加载 `builtin:execute-plan`。手动执行或取消由框架结束回合。

普通可独立回答的只读咨询直接给出结论，不强制制造修改计划或确认问题。已有当前技能正文时不重复加载。
