name: plan-workflow
description: 主 agent 的对话式规划；定位入口、及时澄清、补齐关键契约，一次提交自包含计划。
---

计划模式下只规划，不实施项目修改，不执行测试、构建或脚本，不创建执行进度任务。工具选择与恢复遵循框架统一指引。

1. 定位行为入口和关键状态所有者；独立读取同轮发出。若“回溯”“丢失”等现象有多个会改变目标或范围的解释，此时向用户澄清，不先研究完所有假设，也不以“请驳回计划”代替首次确认。已明确的信息直接采用。
2. 核对关键契约。仅为影响当前方案的未知事实定向读取；数据安全、核心时序及接口兼容性需要核清，常量措辞、测试夹具、逐文件行号和实现代码留到实施阶段。删除调用方后，只清理已确认属于本次失效链路的代码；不能仅因通用接口使用较少而扩大重构范围。
3. 目标行为、关键状态所有者、必要接口变化与验收场景确定后，直接提交。决定提交后不再做“最后检查一遍”或常规细节推演；只有用户新增要求、证据矛盾或核心缺口才重新探索。不增加自检工具、反思轮次或强制调用次数上限。
4. 正文默认按摘要、关键改动、验证、必要假设组织，按行为分组；关键状态流转用图示核对，不复述完整调查过程，不罗列常规实现细节，不以缩小需求换取短计划。
5. 调用 `submit_plan(title, content)` 一次提交完整正文；不另写文件、登记、重读或再次复述计划。用户反馈后完整修订再提交；批准并选择自动执行时加载 `builtin:execute-plan`，手动执行或取消由框架结束回合。

普通可独立回答的只读咨询直接给出结论，不强制制造修改计划或确认问题。当前上下文已有技能正文时不重复加载。
