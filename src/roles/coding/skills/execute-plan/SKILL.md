本技能仅供主 agent 使用；子 agent 只执行明确委派的局部任务，不接管主控工作流。

## 接续计划

仅在已退出 Plan 模式且用户要求执行时实施。模式仍为 Plan 时遵守只读限制，由用户切换模式。

同会话复用仍有效的计划、探索结论和已确认决策；缺失内容或文件变化时按需重读。新会话读取用户指定的计划并核对当前代码。计划代表用户意图，代码事实以现场为准；发现差异时说明影响，只有影响目标、范围或关键取舍才请用户裁决。

没有可定位的计划时询问计划来源，不自行切换模式或套用规划流程。已获执行授权后不重复请求批准。

## 推进实现

主 agent 连续推进实现、诊断、测试和必要文档，分工遵循框架协作规则。复杂工作按可验收结果用 task_* 跟踪，复用已有任务并声明必要依赖；简单工作直接执行。

按依赖顺序处理改动，搜索并复用现有能力，保护用户已有修改。委派只针对边界清楚的独立任务、需要隔离的大量输出或独立复核，不按计划每条改动机械委派一个 coder。

发现错误时加载 `builtin:debugging`，在当前上下文完成根因诊断、修复与验证。bug 修复先建立失败复现或回归测试；新功能覆盖关键行为；机械改动以相关既有检查为准。同步更新受影响的调用方、提示词和读者文档。

新证据导致实现调整时说明原因并更新任务；普通实现选择自主推进，不因某个阶段结束暂停工作。

## 验证与交付

先运行项目的常规快速测试；真实 UI、长耗时集成和打包检查按改动范围显式选择，不把慢测试重新并入常规入口。逐项核对计划验收要求，使用目标项目实际配置的测试和检查，从受影响范围开始，按新增风险扩展。复用针对当前代码的有效验证结果，只有代码变化、失败或新风险才重跑。

普通改动自行审查；涉及安全、数据完整性或复杂共享状态时委派独立 review，使用 shared_context="none"。核对具体发现并修复相关缺陷，按受影响范围再次验证。

相关验证失败时继续诊断和修复；无关既有失败单独报告，不扩大任务范围。确实受阻时明确未完成项、已尝试操作和需要的条件，不虚报完成。任务经实际产物与证据验收后才标记 completed。

交付说明变更结果、实际验证及未覆盖风险。提交、推送或发布遵循用户授权和工具权限。
