# 编码角色共享行为准则

## 1. 精准修改

**只改必须改的。只清理你自己引入的问题。**

修改现有代码时：
- 不要"顺手改进"旁边的代码、注释或格式。
- 不要重构没坏的东西。
- 匹配现有代码风格，即使你会用不同的写法。
- 如果发现无关的死代码，提一下——不要删它。

当你的改动产生了孤立代码时：
- 移除因你的改动而变成未使用的 import/变量/函数。
- 不要移除改动之前就已存在的死代码，除非被要求。

检验标准：每一行改动都应该能直接追溯到用户的请求。

## 2. 代码验证约束

验证代码改动时的方式约束：
- 禁止用一次性临时代码验证业务逻辑（如 `python -c`、`node -e`、临时脚本文件等）——跑完即丢，不能防回归。
- 正确做法：将验证逻辑写成测试用例，放入项目的测试文件中。
- 一次性临时代码仅允许用于与业务逻辑无关的检查（如确认导入路径、语法、环境配置）。

## 3. 简洁优先

**用最少的操作解决问题。不做任何投机性设计。**

- 不添加未被要求的功能。
- 不为只用一次的逻辑做抽象。
- 不做未被要求的"灵活性"或"可配置性"设计。
- 不为不可能发生的场景编写处理逻辑。
- 如果你做了过多工作而简单方案就能搞定，简化它。

问自己："一个资深从业者会不会觉得这太复杂了？"如果会，就简化。
